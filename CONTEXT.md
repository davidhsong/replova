# Replova — Full Project Context

## What It Is

Replova is an AI-powered Google review management SaaS built for restaurants. It helps restaurant owners respond to Google reviews faster and more consistently using AI-generated reply drafts, sentiment analysis, competitor tracking, and weekly digest emails.

**Live URL:** https://replova.vercel.app
**GitHub:** https://github.com/davidhsong/replova

---

## Target Audience

Restaurant owners and operators who:

- Receive Google reviews and want to respond but don't have time to write replies
- Want to monitor their online reputation in one place
- May manage multiple locations (agencies, chains)
- Are non-technical — they need simple UI, magic link auth, and guided onboarding

---

## Core Value Proposition

1. **AI reply drafts** — 3 tone variants (Professional, Warm, Brief) per review, generated by Claude
2. **Google My Business sync** — full review history via GMB API (not just the 5-review Places cap)
3. **Sentiment analysis** — keyword extraction, staff mentions, menu mentions per review
4. **Reputation score** — composite 0–100 score: rating (35%), volume (20%), response rate (25%), sentiment (20%)
5. **Competitor tracking** — monitor competitor ratings and review counts
6. **Review request campaigns** — send review solicitation emails to customers, track opens/clicks
7. **Weekly digest emails** — AI-generated action items + top reviews delivered every Monday
8. **Monthly PDF reports** — white-label for Agency plan

## Auth Flow

1. User completes `/onboard` → `POST /api/restaurants/create` → Supabase sends magic link
2. Magic link → `/auth/callback?code=...` → exchange code → set session cookie → redirect to `/dashboard`
3. `api/auth/magic-link` validates email exists in `accounts` first — unknown emails get 404, not a magic link
4. Google OAuth is for GMB integration only, not user login
5. Session read server-side via ANON key client; all DB writes use service role

## API Routes

### Auth & Google My Business

- `POST /api/auth/magic-link` — sends OTP; checks `accounts` table first
- `GET  /api/auth/google` — initiates Google OAuth for GMB connection
- `POST /api/auth/google/callback` — exchanges code, saves tokens to restaurant row
- `GET  /api/auth/google/locations` — lists GMB locations for the user
- `POST /api/auth/google/set-location` — associates a GMB location with restaurant

### Reviews & Replies

- `POST /api/sync-reviews` — user-triggered sync (fetches + dedupes + generates drafts)
- `POST /api/fetch-reviews` — internal/cron: syncs specific restaurant
- `POST /api/replies/generate` — queues a review for AI reply generation
- `POST /api/replies/approve` — approves a queued reply
- `POST /api/reviews/mark-replied` — marks review as replied (local status only)
- `POST /api/post-reply` — posts approved reply to GMB via API

### Sentiment & Scoring

- `POST /api/sentiment/analyze` — Claude Haiku sentiment analysis, saves keywords & staff mentions
- `GET  /api/score/[restaurantId]` — returns reputation score breakdown

### Review Requests

- `POST /api/review-requests/send` — sends review request email
- `GET  /api/review-requests/list` — lists all requests for a restaurant
- `GET  /api/review-requests/stats` — engagement stats (sent, opened, clicked)
- `GET  /api/review-requests/track` — tracks opens & clicks
- `POST /api/review-requests/upload` — bulk imports customers from CSV

### Competitors

- `GET    /api/competitors` — lists tracked competitors
- `POST   /api/competitors` — adds a competitor (enforces plan limit)
- `DELETE /api/competitors` — soft-deletes (sets active: false)
- `GET    /api/competitors/search` — searches Google Places
- `POST   /api/competitors/auto-discover` — auto-discovers by cuisine/location
- `GET    /api/competitors/comparison` — rating comparison + ranking data

### Billing (Stripe)

- `GET  /api/create-checkout` — creates Stripe checkout (30-day trial); `?plan=starter|growth|agency`
- `GET  /api/billing-portal` — Stripe customer portal (change plan, cancel, update payment)
- `POST /api/webhooks/stripe` — handles: checkout.session.completed, subscription.updated/deleted, invoice events

### Restaurant & Account

- `GET   /api/restaurant` — restaurant info with plan + connectivity status
- `GET   /api/active-location` — active location from cookie
- `PATCH /api/settings` — updates restaurant_settings
- `POST  /api/terms/accept` — records terms acceptance
- `POST  /api/account/delete` — deletes account + all restaurants
- `POST  /api/restaurants/create` — creates restaurant during onboarding

### Cron Jobs (Vercel scheduled, all require `Authorization: Bearer CRON_SECRET`)

| Route                           | Schedule   | Purpose                                  |
| ------------------------------- | ---------- | ---------------------------------------- |
| `/api/cron/sync-all-reviews`    | Every 6h   | Syncs reviews for all active restaurants |
| `/api/cron/process-reply-queue` | Every 15m  | Posts queued replies to GMB              |
| `/api/cron/update-scores`       | Daily 3am  | Recalculates reputation scores           |
| `/api/cron/sync-competitors`    | Daily 4am  | Snapshots competitor ratings             |
| `/api/cron/analyze-sentiment`   | Daily      | Batch analyzes pending reviews           |
| `/api/cron/weekly-digest`       | Monday 9am | Sends weekly digest emails               |

## Sync Logic (lib/syncReviews.ts)

1. Load existing reviews for restaurant (dedup reference)
2. **If GMB connected** (`google_location_name` set): fetch all reviews via GMB API with reply detection
3. **Else**: fall back to Places API (max 5 reviews, no reply detection)
4. For each review:
   - Match by `google_review_name`, then `author::timestamp` composite key
   - Existing: back-fill `google_review_name` if missing; auto-mark `replied` if Google shows a reply
   - New + already replied on Google: insert as `status: 'replied'`
   - New + no reply: insert as `status: 'pending'` → `generateReplies()` → `status: 'drafted'`
5. Returns `SyncResult { source, totalFromGoogle, newlyStored, autoMarkedReplied, repliesGenerated, draftsFailed }`
